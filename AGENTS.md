# AGENTS.md

Python package for scraping NBA data from basketball-reference.com. Modular by design: sources, databases, and web clients are swappable via registry dicts.

## Run environment

- Use the project venv: `.venv/bin/python` (installed editable, so `import scraper` resolves to this repo). System Python won't have the package.
- Deps: `bs4`, `requests`, `lxml`, `curl_cffi` (see `setup.py` `install_requires`). `curl_cffi` is required for the NBA backend (TLS impersonation to reach stats.nba.com/cdn.nba.com). Install with `pip install curl_cffi`.
- No test suite, no CI, no lint/typecheck config. The de-facto smoke test is `useful_testing_stuff.py` — a REPL script that exercises every info type against live basketball-reference hrefs. Run it via the venv to verify engine/source changes.

## Commands / entrypoints

- `bballInitializeDB -o <db_path> [-t sqlite]` → creates the schema (`scripts/initialize_db.py`).
- `bballScrapeYearly -o <db_path> [-d sqlite] [-c native] [-s "basketball reference" | "nba" | "espn"] <years...>` — seasons are given by the year they END in (e.g. `2020` for the 2019-20 season). For `nba`, hrefs are constructed as `/stats/teams/boxscores?Season=<start>-<end>` (e.g. `2021-22`); `season_info` builds the schedule by querying `stats.nba.com/stats/leaguegamelog` for four `SeasonType`s — `Regular+Season`, `Playoffs`, `PlayIn`, `IST` (the IST championship game uses a distinct `006`-prefixed game ID that the regular-season log omits) — and dedups game IDs. The `-c` flag is ignored for `-s nba`: `make_engine` always pairs the NBA source with the `nba_page` pager (curl_cffi), since the `page` pager (plain `requests`) cannot reach stats.nba.com. For `espn`, hrefs are `/espn/season/<year>` and the same pager override applies (`espn_page`, curl_cffi).
- `scripts/scrape_daily.py` is broken (undefined `requests`/`BeautifulSoup` imports, calls non-existent `engine.get_data`) and is NOT registered in `setup.py` entry_points. Don't run or build on it.
- Schema lives ONLY as string constants in `scripts/initialize_db.py` — no migration tooling. Run it before scraping into a fresh DB.

## Non-obvious engine behavior

- `scraper.make_engine(name, pager, database, db_location=None, cache_size=10)` — note `database` is the backend NAME (`"sqlite"`), `db_location` is the file path. Called with only the first three args (as in `useful_testing_stuff.py`), `db_location` is `None` and **all DB writes silently become no-ops** (`pass_none_location`). That's a dry-run mode, not an error.
- Scraping hits the live site: the `page` pager enforces a ~4s delay between requests (class-level `wait_time`), rotates hardcoded user agents, and on HTTP >= 400 polls every 60s until unbanned ("jail"). The `nba_page` pager uses `curl_cffi` TLS impersonation instead of user-agent rotation and handles 404s gracefully (returns empty dict) rather than entering the jail loop. `nba_page` throttles to `wait_time = 2s` by default (tunable: pass `wait_time=` to its constructor), applies a 20s per-request `DEFAULT_TIMEOUT` so stalled connections fail instead of hanging, adds `Referer`/`Origin` headers for `stats.nba.com` requests (required — they time out without them), and impersonates the latest `chrome` TLS profile. Connect/timeout failures are transparently retried (`RETRIES = 3`, 5s backoff); if all retries fail the request is treated like a 404 and returns `{}` so the crawl continues instead of crashing. `espn_page` is JSON-only (no `__NEXT_DATA__` extraction) and follows the same retry contract, with the difference that 404 and other 4xx are terminal instead of entering the jail loop. Every actual network request logs a `requesting <href>` line followed by `done <href> in <secs>s (HTTP <status>)`, so progress is visible even on a slow crawl. Full seasons take many minutes and require network; logs go to stdout and are line-buffered, so a `> nba.log` redirect shows output as it happens instead of holding it until exit.

## Logging

- Logs go to **stdout** through a single `StreamHandler` on the `scraper` logger (`scraper/debug.py`). The handler flushes every record, and `configure()` also sets `line_buffering=True` on stdout, so redirected logs (`bballScrapeYearly ... > nba.log`) stream as they are produced — the old bare `print()` calls were block-buffered and hid everything until process exit.
- Line format is `HH:MM:SS [LEVEL] module: message`, e.g. `11:49:06 [INFO] scraper.backend_pagers.espn_page: done /athletes/3934672 in 0.1s (HTTP 200)`. The old `[ Request ]:`/`[   Error    ]:` prefixes are gone.
- `make_engine` calls `configure()` if no handler is attached yet, so a bare `import scraper` still logs at INFO. `bballScrapeYearly`/`bballInitializeDB` accept `-q` (WARNING), `-qq` (ERROR) and `-v` (DEBUG) and configure before scraping.
- Level conventions: request lifecycle (`requesting`/`done`/`from cache`) is INFO; per-row detail is DEBUG; data-quality issues (missing quarters, award/coach sub-fetch failures, period-list mismatch) are WARNING; the basketball-reference jail, unrecovered request failures, and non-data exceptions are ERROR.
- **Assumptions are reported, not silent**: whenever a value is substituted because the source publishes no data, `assume(location, field, value, reason, context=..., log=...)` logs the first sighting of each (location, field, value) triple at INFO and every sighting at DEBUG. So a whole NBA season of `Shoots='R'` defaults (347 players) is one INFO line, with every affected player visible under `-v`. Sites: `nba.py get_shoots` and `_stat` missing headers (a misspelled header was previously a silent zero), `espn.py` `Shoots`/`High_School`/`Debut_Date`/`Duration`/coach `Birthday`/`executive_info`, `espn.py _int` parse failures, and every `error_wrap` default (see below).
- `error_wrap` (31 sites, 27 in `basketball_reference.py`) still catches a failing field getter and returns a default (`0`/`''`/`False`/`[]`/explicit `default=`) instead of raising — the contract is unchanged. It now logs the substituted value via `assume` at INFO instead of `[   Error    ]: Could not fill the field.`, and passes the exception through: a data-shaped exception (`KeyError`/`IndexError`/`AttributeError`/`TypeError`/`ValueError`) is treated as an assumption, while anything else (`NameError`, `AssertionError`, ...) additionally logs `unexpected <Type> filling <location>.<field>` at ERROR so real breakage is not mistaken for a routine fallback.
- Injured / did-not-play players are intentionally excluded from game data (`game_data.injury_check`). The old "Two pointers" stat was renamed to `Field_Goals`. Team game-by-team totals go to `team_games` from the boxscore `TeamStats` resultSet (home + away totals rows); `team_data` deliberately omits `PM`/`Player_ID` because `team_games` has no such columns (`zip(*data.values())` in `sqlite.save_data` truncates to the shortest column, so a stray empty list silently drops all rows). Quarterly data (`player_quarters`/`team_quarters`) is fetched per period by re-requesting `boxscoretraditionalv2` with `RangeType=1&StartPeriod=N&EndPeriod=N` for each period played (count from `homeTeam.periods`, which also carries a per-period `periodType` of `REGULAR`/`OVERTIME`) — this adds one stats.nba.com request per period on top of the whole-game boxscore. The count is cross-checked against the page's own `period` field (a mismatch is logged and the period list wins) and is deliberately **uncapped**, because any ceiling would silently truncate a long overtime game and, since the whole-game rows are summed from these same quarters, a truncated loop yields under-counted totals that look real. `_get_boxscore`'s `EndPeriod` default is likewise `14` rather than `10` so the `RangeType=0` URL can't truncate an overtime game (verified to not change that response). A failed period is logged (`missing per-quarter data for periods ...`, WARNING) and skipped; it does NOT truncate the remaining quarters, and the periods that did succeed are still written. **But a missing period invalidates the whole-game sum**: if `RangeType=0` was empty *and* any period is missing, the whole-game tables are deliberately left EMPTY and logged (`not writing whole-game rows for ...`, WARNING) instead of writing an under-counted total. This is deliberate — an absent row is recoverable, a plausible-looking wrong one is not. An out-of-date DB still holding whole-game rows summed from incomplete quarters should be re-scraped.
- The NBA backend's whole-game boxscore (`RangeType=0`) is requested first and used when it returns rows. stats.nba.com currently answers that response with **empty `resultSet`s** for many games (observed for the 2024-25 and 2025-26 seasons) while the per-period `RangeType=1` responses stay populated, which used to leave `player_games`/`team_games` silently empty. When (and only when) the `RangeType=0` response yields no `Points`, the whole-game tables are instead rebuilt by **summing the per-period rows that the crawl already fetched** — no extra request is issued. `_QuarterTotals` (in `backend_sources/nba.py`) accumulates those rows keyed by player/team href; `_ADDITIVE_COLUMNS` lists the 16 output columns that sum (`Seconds` … `Points`, `PM`) while every other column (`Win`/`Home`/`Season`/`Game_ID`/`*_ID` hrefs) is constant within one game and is carried from the last period that saw that key — `Season` is numeric but must never be summed. Rebuilding via `player_totals.table(columns)`/`team_totals.table(columns)` guarantees every column list is the same length, sidestepping the `zip(*data.values())` truncation hazard. When the fallback fires it is logged (`whole-game boxscore empty for game ...; summed the per-quarter rows instead ...`, INFO), and it only fires when the period loop was complete (see the period-count rules above). Sums were verified exact against nba.com's own whole-game boxscore on games where both are available. Stats column names are easy to get wrong and fail *silently*, because `_stat()` coerces a missing header to `0` rather than raising: stats.nba.com spells turnovers **`TO`**, with no `TOV` column anywhere in `boxscoretraditionalv2`/`v3` or `boxscoreadvancedv3` (`TO` is present in both `RangeType=0` and `RangeType=1`, so quarterly turnovers cost no extra request). Every other header the source reads (`MIN`, `FGM`, `FGA`, `FG3M`, `FG3A`, `FTM`, `FTA`, `OREB`, `DREB`, `AST`, `STL`, `BLK`, `PF`, `PTS`, `PLUS_MINUS`, `PLAYER_ID`, `TEAM_ID`, `GAME_ID`) was audited against the live headers and is spelled correctly. A header going missing is reported via `assume` once per run at INFO rather than zeroing silently. Unused-but-available columns: `REB`, `TEAM_NAME`, `TEAM_ABBREVIATION`, `TEAM_CITY`, `PLAYER_NAME`, `NICKNAME`, `START_POSITION`, and the percentages `FG_PCT`/`FG3_PCT`/`FT_PCT` (the schema has no columns for them). The other sources are unaffected — `espn.py` reads ESPN's `turnovers` and `basketball_reference.py` reads bbref's `tov`.
- Every `get_*` method on the engine assigns stable integer IDs, persists them to the `id_cache` table, and saves each object once. Re-running over the same DB is safe because hrefs are looked up in the id cache.

## Architecture / adding a backend

- Facade is `scraper/engine.py`: `make_engine` picks concrete classes from the `sourceEngines` / `pagerEngines` / `dbEngines` registries. `basketball reference` + `native` + `sqlite` are fully implemented; `nba` is implemented with `nba_page` (curl_cffi TLS impersonation) and `nba.py` source (parses `__NEXT_DATA__` from nba.com HTML + stats.nba.com JSON for boxscores); `espn` is implemented with `espn_page` (curl_cffi, JSON only) and `espn.py` source (sports.core.api.espn.com for schedules/athletes, site.api.espn.com for boxscores and standings).
- The ESPN backend uses `espn_page`, a JSON-only curl_cffi pager. Because ESPN serves every endpoint as JSON there is no `__NEXT_DATA__`/soup fallback, and no per-host header logic. `espn_page` retries connection failures, 5xx, and 429 (`RETRIES = 3`, 5s backoff, then `{}`); it treats 404 and other 4xx as terminal because ESPN's Akamai WAF answers non-API paths with 403 and retrying that cost ~15s of pointless backoff. It throttles to `wait_time = 1s`, uses a 20s `DEFAULT_TIMEOUT`, and defaults `cache_size` to 32 so an event summary survives the interleaved team/player lookups that `game_info` and `game_data` trigger against the same URL. All ESPN hrefs are namespaced `/espn/...` because the engine's id-cache dicts are class-level and shared, so bare numeric ESPN ids would otherwise alias against the other sources.
- ESPN data lives on three hosts, so `espn.py` passes `base_url=` per call: `sports.core.api.espn.com/v2/...` (season schedules, athlete bios, team names), `site.api.espn.com/apis/site/v2/...` (game summaries, hence all boxscores), and `site.api.espn.com/apis/v2/...` (standings).
- ESPN game classification keys off the summary header's own `header.season.type`: `3`=playoffs, `5`=play-in, `2`=regular. There is no in-season-tournament type — IST games sit in the regular bucket and are identified by their `header.gameNote` label (`'NBA Cup - Group Play/Quarterfinals/Semifinals'`, `'NBA Cup Championship'`); `competition.neutralSite` was the old (broken) heuristic — only the Las Vegas knockout games are neutral (61 of 67 tournament games are at home arenas), and the Paris/Mexico City games are neutral but ordinary regular-season games, so neutral-site games now simply count in the category they fall into. `header.season.year` gives the season outright, so a game scraped on its own still classifies correctly; `_EVENT_TYPE` (built by `season_info._fetch` while enumerating each schedule type) is only a fallback. `season_info` enumerates `types/{2,3,5}`, but All-Star games live *inside* the regular-season type bucket (the events enumeration is `$ref`-only, so they cannot be filtered at schedule time) and are instead excluded by a `_skip_reason` gate on `header.gameNote` (`'NBA All-Star ...'`) at the top of `game_data._fetch` and `game_info._fetch` — skipped with a WARNING, no rows, and no id_cache mark, so the next run retries and logs again (same shape as the postponed-event gate right below it). The gate deliberately fail-opens: only a positive match on the label excludes an event.
- ESPN **team** hrefs are season-qualified (`/espn/team/<id>/<season>`) — one id per season, because `team_info` has a `Season` column. ESPN **player** hrefs are deliberately season-**less** (`/espn/athlete/<id>`, from `_player_href`): `player_info` has no `Season` column and `Player_ID` is its PK, so a player is one row per career. Putting the season in the href makes the id_cache treat each season as a separate entity and mint a fresh `Player_ID` every season, which `player_games.Player_ID` then FKs to — silently breaking cross-season aggregation (pre-fix, two seasons scraped together produced 44 `player_info` rows for 37 distinct players). `_player_href` therefore takes no season, and `player_info.__init__` reads the unscoped `/athletes/<id>` core-api resource: the only season-dependent fields on that payload are `team` and `experience.years`, neither of which is stored, and the stored fields were verified byte-identical to the season-scoped resource. Season-accurate `Wins`/`Losses`/`League_Ranking`/`Playoff_Appearance` are overlaid from `_SEASON_STANDINGS`, built by `season_info._fetch` from the standings endpoint: ESPN returns standings in an arbitrary order (not sorted by wins), so league-wide rank is derived by sorting all 30 by `(-wins, +losses)`, and `Playoff_Appearance` is `0 < playoffSeed <= 8` (the 8 seeds per conference), which is exact and avoids fetching every playoff boxscore.
- ESPN boxscore shapes differ from the other sources: `boxscore.teams[].statistics` is a flat `{name, displayValue}` list (not the `keys`/athletes format), has no `points` (score comes from `header.competitions[].competitors[]`) and no minutes — so team `Seconds` is `len(linescores) * 720`, which matches the basketball-reference convention (NBA stores summed player-minutes instead, a pre-existing cross-source inconsistency). Player stats come from `zip(statistics[0].keys, athletes[].stats)` and `didNotPlay`/zero-minute players are excluded.
- Pattern: abstract lazy-fetch classes in `backend_*/abstract.py` expose `@require_fetch` properties; the concrete source (e.g. `backend_sources/basketball_reference.py`) implements `_fetch()` and overrides the 8 `*_info` factory methods plus `get_id_cache`. A new source = new class + registration in the `engine.py` dicts. `pager.get(href, cache=True, base_url=None)` builds the request URL as `base_url + href`, defaulting `base_url` to the pager's own `base_url`; pass an explicit `base_url` to hit a different host (the NBA source does this for `stats.nba.com` API calls).
- The NBA backend uses a separate pager (`nba_page`) that uses `curl_cffi` for TLS impersonation (required to reach stats.nba.com/cdn.nba.com). It extracts `__NEXT_DATA__` JSON from nba.com HTML pages and returns parsed dicts. Stats API calls go to `stats.nba.com/stats/boxscoretraditionalv2` for boxscore data.
- NBA team hrefs are season-qualified: `/team/<teamId>/<season>` (season = the year it ends, e.g. `/team/1610612738/2024`). The id_cache treats each season-qualified href as a distinct key, so a franchise gets one `team_info` row/`Team_ID` per season. `game_info`/`game_data` build these from the game's derived season, and `team_info` strips the season for the nba.com team-page request (nba.com pages aren't season-scoped). Season-accurate `Wins`/`Losses`/`League_Ranking`/`Playoff_Appearance` are overlaid from `_SEASON_STANDINGS`, which `season_info._fetch` builds from two stats.nba.com calls: `leaguestandings` (regular-season W/L, overall rank 1-30) and `leaguegamefinder` (`SeasonType=Playoffs`, for the exact set of teams that appeared in playoff games). Without standings data (e.g. scraping a game directly), `team_info` falls back to the live team page with the season taken from the href. `season_info` also skips fetching the boxscores page entirely (its data all comes from the stats.nba.com APIs).
- `game_info` classification for NBA keys off the `gameId` prefix — `004`=playoffs, `005`=play-in, `006`=in-season tournament (the IST championship), and anything else falls back to checking `gameSubtype`/`gameLabel` (lowercased, e.g. `in-season`/`Emirates NBA Cup`) before defaulting to `regular`. All-Star games are excluded from the schedule.
- Data coverage gaps in the ESPN backend: ESPN publishes no per-quarter player/team stat splits (only per-team `linescores` scores), so `player_quarters`/`team_quarters` are deliberately left empty. It also exposes no game wall-clock duration — a finished game's `status` carries only `STATUS_FINAL` and `boxscoreMinutes` is a boolean flag, not a value — so `game_info.Duration` is stored as `0` rather than estimated. `executive_info` is a pure stub (`site /teams/<id>/executives` answers `{}` and there is no core-api front-office endpoint), so `Executive_ID` is always 0. `teams/{id}/roster` returns an empty `athletes` array, so rosters are never fetched. `player_info` has no `highSchool` field (`High_School` is always 0) and no shooting-hand data, so `Shoots` defaults to `'R'`; `Debut_Date` is left empty because ESPN exposes no debut date. Referee profiles are filled from `gameInfo.officials` (name only — ESPN has no referee pages or ids and no jersey numbers, so `Number` is 0 and `Birthday` is empty), and referees are keyed by a name slug, so a name collision would alias two officials. Athlete bios come from the season-scoped core-api endpoint, which does supply `dateOfBirth`, `height`, `birthPlace`, `draft` (year/round/pick/team) and `experience.years`; `Draft_Team` is resolved via a cached core-api team lookup.
- ESPN season awards DO exist: `season_info._fetch` reads `seasons/<season>/awards/<id>` for the six awards with columns (MVP `33`, ROY `35`, MIP `36`, DPOY `39`, SixMOTY `40`, Finals MVP `43`), verifying each record's `name` before trusting its `winners[0]`. Each winner's athlete `$ref` is already the season-**less** player href game data builds, so an award winner and a boxscore appearance resolve to the same `Player_ID` — a player who wins two of the six columns (e.g. MVP and Finals MVP) shares one id across both, and the href is stable enough to FK from `season_info` to `player_info`. The Finals MVP's `team.$ref` is used as **Champion** (the schedule holds event ids, not results, so there is no cheaper source). Awards are per-season best-effort: if a season's awards are not published yet the numeric columns stay 0 and the hrefs stay `None` (they must be `None`, not `''`, because `empty_href_wrap` only short-circuits a `None` href). Core-api publishes 20 awards; the 14 without columns (All-NBA teams, All-Star MVP, NBA Cup MVP, etc.) are ignored.
- ESPN coaches ARE available, but not season-accurately. `season_info._fetch` maps each team to its head coach by asking `seasons/<season>/teams/<teamId>/coaches` (the season-scoped coach list/profile omits `team` for roughly a quarter of the league, so mapping through it drops teams); `team_info._fetch` reads the resulting `_SEASON_COACHES` to fill `Coach_ID`. Coach hrefs are deliberately **not** season-qualified (`/espn/coach/<personId>`, one `coach_info` row per career, because the `coaches` table has no `Season` column). Wins/Losses come from the coach's unscoped `/coaches/<id>` `careerRecords[0]` (the "Total" record), so they are **career-to-date, not as of the scraped season** — a historical season stores whatever the record was when the crawl ran, which is the same semantics as the basketball-reference source. ESPN has no coach date of birth, only a birth place, so `coach_info.Birthday` stays empty. Coach data is skipped for a game scraped on its own, leaving `Coach_ID` at 0 just like the standings fallback.
- Data coverage gaps in the NBA backend: executive profiles and coach career records have no equivalent on nba.com and return defaults. Referee profiles are filled from the game page's `__NEXT_DATA__.game.officials` (name + jersey number; no network request — nba.com has no `/referee/<id>` pages), so `referee_info.Birthday` stays empty for NBA. Historical season awards (MVP/DPOY/etc.) and champion are also stubbed. Boxscore data requires curl_cffi TLS impersonation to reach stats.nba.com. nba.com also exposes no shooting-hand data, so `player_info.get_shoots` uses the `debug.error_wrap` wrapper to default the `Shoots` column to `'R'` (satisfying the `Shoots LIKE "L" OR "R"` CHECK constraint).
- `game_info.Date` is the ISO calendar date of tip-off in **US Eastern** (`YYYY-MM-DD`) for every source — same game, same string, across sources. ESPN's `header.competitions[0].date` is a UTC instant (`'2024-11-13T00:00Z'`, minute precision), so it goes through `abstract.eastern_date()` (zoneinfo `America/New_York`, naive input treated as UTC, unparseable input falls back to `[:10]` via `assume`); the old raw `[:10]` truncation stored the **UTC** date and was +1 day for any game tipping at/after 7 PM EST / 8 PM EDT — measured at 929/1318 (70%) of the 2024-25 season. NBA's `gameCode` date prefix (`20241022/...`) is already Eastern (verified against ESPN's UTC instants: evening games differ by exactly one day) and basketball-reference's title date is already Eastern too (bbref prints Eastern times — its scorebox shows `10:00 PM, October 22, 2024` for a 7 PM PT tip) but was stored as `'Month D, YYYY'` and is now parsed to ISO in `get_date`. **basketball-reference `get_season` derives Season from that parsed date** (month ≥ 10 → year+1, else year — the same `2023-24 → 2024` convention); the old `soup.select('u')[1]` selector broke when bbref removed every `<u>` tag, which made every `game_info` row hit the `Season > 1990` CHECK and be silently dropped while id_cache still marked the game complete (symptom: `CHECK constraint failed: Season > 1990` printed by `sqlite.execute`). Old DBs keep their skewed dates — a fresh crawl is required, there is no migration tooling.
