# AGENTS.md

Python package for scraping NBA data from basketball-reference.com. Modular by design: sources, databases, and web clients are swappable via registry dicts.

## Run environment

- Use the project venv: `.venv/bin/python` (installed editable, so `import scraper` resolves to this repo). System Python won't have the package.
- Deps: `bs4`, `requests`, `lxml`, `curl_cffi` (see `setup.py` `install_requires`). `curl_cffi` is required for the NBA backend (TLS impersonation to reach stats.nba.com/cdn.nba.com). Install with `pip install curl_cffi`.
- No test suite, no CI, no lint/typecheck config. The de-facto smoke test is `useful_testing_stuff.py` — a REPL script that exercises every info type against live basketball-reference hrefs. Run it via the venv to verify engine/source changes.

## Commands / entrypoints

- `bballInitializeDB -o <db_path> [-t sqlite]` → creates the schema (`scripts/initialize_db.py`).
- `bballScrapeYearly -o <db_path> [-d sqlite] [-c native] [-s "basketball reference" | "nba"] <years...>` — seasons are given by the year they END in (e.g. `2020` for the 2019-20 season). For `nba`, hrefs are constructed as `/stats/teams/boxscores?Season=<start>-<end>` (e.g. `2021-22`); `season_info` builds the schedule by querying `stats.nba.com/stats/leaguegamelog` for four `SeasonType`s — `Regular+Season`, `Playoffs`, `PlayIn`, `IST` (the IST championship game uses a distinct `006`-prefixed game ID that the regular-season log omits) — and dedups game IDs. The `-c` flag is ignored for `-s nba`: `make_engine` always pairs the NBA source with the `nba_page` pager (curl_cffi), since the `page` pager (plain `requests`) cannot reach stats.nba.com.
- `scripts/scrape_daily.py` is broken (undefined `requests`/`BeautifulSoup` imports, calls non-existent `engine.get_data`) and is NOT registered in `setup.py` entry_points. Don't run or build on it.
- Schema lives ONLY as string constants in `scripts/initialize_db.py` — no migration tooling. Run it before scraping into a fresh DB.

## Non-obvious engine behavior

- `scraper.make_engine(name, pager, database, db_location=None, cache_size=10)` — note `database` is the backend NAME (`"sqlite"`), `db_location` is the file path. Called with only the first three args (as in `useful_testing_stuff.py`), `db_location` is `None` and **all DB writes silently become no-ops** (`pass_none_location`). That's a dry-run mode, not an error.
- Scraping hits the live site: the `page` pager enforces a ~4s delay between requests (class-level `wait_time`), rotates hardcoded user agents, and on HTTP >= 400 polls every 60s until unbanned ("jail"). The `nba_page` pager uses `curl_cffi` TLS impersonation instead of user-agent rotation and handles 404s gracefully (returns empty dict) rather than entering the jail loop. `nba_page` throttles to `wait_time = 2s` by default (tunable: pass `wait_time=` to its constructor), applies a 20s per-request `DEFAULT_TIMEOUT` so stalled connections fail instead of hanging, adds `Referer`/`Origin` headers for `stats.nba.com` requests (required — they time out without them), and impersonates the latest `chrome` TLS profile. Connect/timeout failures are transparently retried (`RETRIES = 3`, 5s backoff); if all retries fail the request is treated like a 404 and returns `{}` so the crawl continues instead of crashing. Every actual network request logs a `[ Request ] requesting <href>` line followed by `[ Request ] done <href> in <secs>s (HTTP <status>)`, so progress is visible even on a slow crawl. Full seasons take many minutes and require network; expect `[ Request ]`/`[ Error ]` debug prints on stdout.
- Injured / did-not-play players are intentionally excluded from game data (`game_data.injury_check`). The old "Two pointers" stat was renamed to `Field_Goals`. Team game-by-team totals go to `team_games` from the boxscore `TeamStats` resultSet (home + away totals rows); `team_data` deliberately omits `PM`/`Player_ID` because `team_games` has no such columns (`zip(*data.values())` in `sqlite.save_data` truncates to the shortest column, so a stray empty list silently drops all rows). Quarterly data (`player_quarters`/`team_quarters`) is fetched per period by re-requesting `boxscoretraditionalv2` with `RangeType=1&StartPeriod=N&EndPeriod=N` for each period played (count from `homeTeam.periods`, capped at 8) — this adds one stats.nba.com request per period on top of the whole-game boxscore. A failed period is logged (`[ game_data ]: missing per-quarter data ...`) and skipped; it does NOT truncate the remaining quarters.
- Every `get_*` method on the engine assigns stable integer IDs, persists them to the `id_cache` table, and saves each object once. Re-running over the same DB is safe because hrefs are looked up in the id cache.

## Architecture / adding a backend

- Facade is `scraper/engine.py`: `make_engine` picks concrete classes from the `sourceEngines` / `pagerEngines` / `dbEngines` registries. `basketball reference` + `native` + `sqlite` are fully implemented; `nba` is implemented with `nba_page` (curl_cffi TLS impersonation) and `nba.py` source (parses `__NEXT_DATA__` from nba.com HTML + stats.nba.com JSON for boxscores); `espn.py` is an empty license-header stub.
- Pattern: abstract lazy-fetch classes in `backend_*/abstract.py` expose `@require_fetch` properties; the concrete source (e.g. `backend_sources/basketball_reference.py`) implements `_fetch()` and overrides the 8 `*_info` factory methods plus `get_id_cache`. A new source = new class + registration in the `engine.py` dicts. `pager.get(href, cache=True, base_url=None)` builds the request URL as `base_url + href`, defaulting `base_url` to the pager's own `base_url`; pass an explicit `base_url` to hit a different host (the NBA source does this for `stats.nba.com` API calls).
- The NBA backend uses a separate pager (`nba_page`) that uses `curl_cffi` for TLS impersonation (required to reach stats.nba.com/cdn.nba.com). It extracts `__NEXT_DATA__` JSON from nba.com HTML pages and returns parsed dicts. Stats API calls go to `stats.nba.com/stats/boxscoretraditionalv2` for boxscore data.
- NBA team hrefs are season-qualified: `/team/<teamId>/<season>` (season = the year it ends, e.g. `/team/1610612738/2024`). The id_cache treats each season-qualified href as a distinct key, so a franchise gets one `team_info` row/`Team_ID` per season. `game_info`/`game_data` build these from the game's derived season, and `team_info` strips the season for the nba.com team-page request (nba.com pages aren't season-scoped). Season-accurate `Wins`/`Losses`/`League_Ranking`/`Playoff_Appearance` are overlaid from `_SEASON_STANDINGS`, which `season_info._fetch` builds from two stats.nba.com calls: `leaguestandings` (regular-season W/L, overall rank 1-30) and `leaguegamefinder` (`SeasonType=Playoffs`, for the exact set of teams that appeared in playoff games). Without standings data (e.g. scraping a game directly), `team_info` falls back to the live team page with the season taken from the href. `season_info` also skips fetching the boxscores page entirely (its data all comes from the stats.nba.com APIs).
- `game_info` classification for NBA keys off the `gameId` prefix — `004`=playoffs, `005`=play-in, `006`=in-season tournament (the IST championship), and anything else falls back to checking `gameSubtype`/`gameLabel` (lowercased, e.g. `in-season`/`Emirates NBA Cup`) before defaulting to `regular`. All-Star games are excluded from the schedule.
- Data coverage gaps in the NBA backend: executive profiles and coach career records have no equivalent on nba.com and return defaults. Referee profiles are filled from the game page's `__NEXT_DATA__.game.officials` (name + jersey number; no network request — nba.com has no `/referee/<id>` pages), so `referee_info.Birthday` stays empty for NBA. Historical season awards (MVP/DPOY/etc.) and champion are also stubbed. Boxscore data requires curl_cffi TLS impersonation to reach stats.nba.com. nba.com also exposes no shooting-hand data, so `player_info.get_shoots` uses the `debug.error_wrap` wrapper to default the `Shoots` column to `'R'` (satisfying the `Shoots LIKE "L" OR "R"` CHECK constraint).
